# ADR 0003 · Структура на хранилището

Дата: 7 ноември 2026 г. · Статус: частично отменено

Актуалната структура и указанията за нов код са в [README](../../README.md) и [ръководството](../dev-guide.md). Описанията по-долу на npm workspace, Python като производствен вход и местата за нов код са отменени. Останалият текст се пази като историческо решение.

## Контекст

Сайтът е производствената система. Общите директории на прототипа смесват действащи екстрактори, строители, браузърни проверки и исторически инструменти. Необходима е структура с ясни места за нов код, без промяна на публичните адреси, числата или последователността на обработката.

## Решение

```text
apps/
  web/                 app/, workers/ (api/), client/, public/, migrations/, scripts/, конфигурация
pipeline/
  budget_pipeline/     sources/, extract/, build/, validate/, cli.py
  requirements.txt     декларация на Python зависимостите
  requirements.lock    закованата Python среда
  Dockerfile           референтната среда Python 3.12
  environments.json    конфигурация на операторските среди
  pyproject.toml       метаданни на Python пакета
data/
  originals/           оригинални документи; политиката за включване е в .gitignore
  inputs/              замразени входни JSON файлове и ръчно поддържани входове
  cache/               междинни резултати и изследователски извлечения, извън git
  release/             единственото включено в git копие на публикуваното издание
  sources.yaml         източници и произход на междинните входове
  datasets.yaml        производители, слоеве и входове на наборите
  originals.sha256     контролните суми на запазените входове
tests/
  e2e/                 браузърни проверки и помощници
  release/             съвместимост, регистър и възстановяване
reference/
  prototype/           исторически HTML и инструменти
  mock/                исторически проверки и сравнения
docs/
  adr/                 архитектурни решения
```

Коренният `package.json` управлява npm workspace `apps/web`. `npm ci` се изпълнява в корена с един lockfile и същите заковани версии. Скриптовете `npm run build`, `npm run typecheck` и `npm run dev` препращат към сайта.

Клиентските модули остават в `client/` до етап 2 на ADR 0002. При сглобяване те се публикуват под `/js/`, статичните файлове от `public/` - под досегашните си адреси, а `data/release/` - под `/data/`. Статичният сървър за разработка и браузърните проверки съставят временна директория в `tmp/` със символни връзки към тези три източника. Данните не се дублират в git.

Нов екстрактор се добавя в `pipeline/budget_pipeline/extract/` според семейството документи; строител - в `build/`; придобиване - в `sources/`; проверка на данните - в `validate/`. Извлечените временни резултати се записват в `data/cache/`. Ръчно поддържаните входове се добавят в `data/inputs/` с регистрация в `sources.yaml`. Съществуващите замразени извлечения също остават там: текущото сглобяване ги чете, без да изпълнява всички исторически производители. Техният произход и производител са запазени в регистъра. Премахването им изисква отделна промяна на възпроизводимото сглобяване.

Историческите тагове остават непроменени. Слоят за терминология чете замразените подредени замени от `data/inputs/wording.json`; произходът от `mock-v2` и `mock-v4` е записан с път и blob SHA в `data/sources.yaml`. Сглобяването не изисква тези тагове. Историческите манифести и всички байтове в `data/release/` остават непроменени, включително записаните в тях стари пътища. Полетата на каталога, които сочат публични файлове (`data/...`), остават URL пътища.

## Последици

Преместването променя само местоположенията, импортите и конфигурацията на инструментите. Новите промени се проверяват с TypeScript, регистрите, валидаторите на данните, браузърните проверки и проверките на изданията. Историческите инструменти не се изпълняват в CI. Виртуалните среди, браузърите и резултатите от проверките се пазят в игнорираната директория `tmp/`.

## Именуване на Python модулите

Директорията определя слоя, а името на модула определя предмета: `build.fiscal`, `extract.kfp_full`, `validate.execution_reports`. Имената са описателни, в snake*case, без повторение на слоя (`bd*`, `vd*`, `extract*`, `build\_`) и без версии. Общите операции по данни са в `build.data_io`, а помощниците за проверки в `validate.checks`. Историческите имена в публикуваните издания остават непроменени.

## Пакетни граници и изпълнение

Поддържаният вход за всеки Python модул на обработката е `python -m budget_pipeline.<слой>.<предмет>`. Средата се инсталира от двата lockfile-а, след което `pip install --no-deps -e pipeline` регистрира пакета. Обвивката `budget` добавя директорията pipeline към PYTHONPATH и изпълнява `python -m budget_pipeline.cli`; Docker задава PYTHONPATH=/repo/pipeline за монтираното хранилище. Изисква се Python 3.12 или по-нов.

`cli.py` запазва обработката на аргументите и операциите по изданията до планирания пренос към TypeScript. Производствената последователност е единствено `build.rebuild`, използвана от `budget build`. Общите строители в `build.datasets` са вътрешна стъпка; изпълнението на модула също насочва към цялата последователност.

Старият shell ред, генерирането на M01–M05 и подгрупите за старото сглобяване са само в reference/. Производственият пакет не ги импортира, изпълнява или чете. Замразените входове без действащ производител имат producer: null и отделна историческа бележка. Единствените останали примерни набори са M06/M07; производителят и независимият валидатор са ограничени точно до тях. Единственият guide модул се използва за текущите редакционни текстове.

Скриптовете за сайта и интеграционните тестове се изпълняват като модули от корена (`python -m apps.web.scripts.build`, `python -m tests.e2e.screens`), без да се включват в дистрибуцията на pipeline.

Празният release пакет и placeholder директорията pipeline/tests са премахнати. Отделяне на Python операциите и нов Python test пакет не се въвеждат преди поетапния пренос към TypeScript.
