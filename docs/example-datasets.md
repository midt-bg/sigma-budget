Тук са описани само M06 и M07. Производителят е `python -m budget_pipeline.build.examples`, а независимата проверка е `python -m budget_pipeline.validate.examples`. Премахването на тези два набора е отделна продуктова промяна.

## 7. M06 `mock/measure-labels.json` — S12, S08, S01 · M07 `mock/tax-assumptions.json` — S18

### 7.1 M06 (всеки id на мярка от `measures.json`, 52)
```jsonc
{ "meta": { …, "label":"РЕДАКЦИОННИ ЕТИКЕТИ", "notice":"…",
            "personas":[ {"label":"Работещ","hint":"наети и самонаети, включително когато търсят работа"}, … ],    // Работещ, Пенсионер, Родител, Шофьор, Бизнес, Студент
            "riskKinds":[ {"id":"stated","label":"Посочена сума"}, {"id":"indicative","label":"Индикативна сума"},
                          {"id":"avoided","label":"Индикативна сума на избегнат разход"}, {"id":"none","label":"Без посочена сума"} ],
            "counts":{ "measures":52,"noGroup":11,"withDate":16,"withLegalBasis":14,
                       "byGroup":{"Работещ":17,"Пенсионер":3,"Родител":2,"Шофьор":4,"Бизнес":29,"Студент":3} },
            "note":"…", "realFields":["items[].id","items[].evidence","items[].riskEvidence","items[].legal","items[].sinceText","items[].riskKind","items[].since"],
            "modelFields":["items[].affects","items[].payer","items[].winner","items[].risk"] },
  "items":[ { "id":"kr1", "affects":["Работещ","Бизнес"], "payer":"…", "winner":"…", "risk":"…", "riskKind":"stated",
              "evidence":"…", "riskEvidence":"…", "since":"2026-08-01", "sinceText":"…", "legal":"…",
              "mock":true, "why":"Примерен редакционен етикет по текста на мярката; не е официална класификация и не е проверен." }, … ] }   // 52, редът на measures.json
```
* `id` = id от `measures.json` (kr1–kr8, kx1–kx9, kn1–kn7, d8-1…d8-14, d9-1…d9-6, p8-1…p8-8), всеки точно веднъж.
* `affects` ⊂ шестте персони; **`[]` значи, че според текста никоя персона не е пряко засегната** (11 мерки). Където
  текстът не казва кой плаща или кой печели, `payer`/`winner` гласят „Не е посочено в текста“.
* `evidence` е дословен откъс от текста на самата мярка (проверява се от валидатора спрямо `measures.json`), както и
  `riskEvidence` (29 елемента) и `legal` (правно основание, 14 елемента). `riskKind` следва състоянието на оценката на мярката
  (stated 35, indicative 1, avoided 1, none 15); `risk` е кратка бележка за вида на оценката и собствената уговорка на текста.
* `since` (ISO дата, 13 елемента) се пише само когато датата е в данните или текста на мярката; където текстът дава само
  месец или година, `sinceText` (3 елемента) държи дословната фраза. Всички етикети са редакционни и непроверени: печатай `meta.label`.
* В списъка с персони няма „получател на социални помощи“ или „хора с увреждания“ (отворен въпрос 4 от плана).

### 7.3 D22 `glossary.json` (S03 и изскачащите термини) · D23 `guide.json` (S02) — реален текст, не примерен
И двата са собственият текст на работната група, пренесен в JSON: `status:"real"`, `source:["wg"]`, `mock:false`, `asOf:"2026-10-01"`
(датата на изходните текстове), `retrieved:"2026-10-02"`, без `label`, без `why`. В тях няма бюджетна цифра (числата в
примерите от речника са условни, а `intro.disclaimer` го казва). `pipeline/budget_pipeline/build/editorial.py` копира всяка дума програмно
от по-ранните текстове на групата (`data/inputs/glossary.json`; текстът на пътеводителя) и променя само
формата; валидаторът (група `TEXT`) проверява номерацията, категориите, връзките между термини, всяка връзка спрямо `apps/web/client/routes.js`,
авторството и идентичността при наново сглобяване. Авторството е общо: „Работна група „Бюджет на светло““.

```jsonc
// glossary.json — 64 термина, 5 категории, 7 реда връзки, 7 източника
{ "meta": { "id":"D22", "title":"Речник: бюджетът на разбираем език", "status":"real", "source":["wg"], "sourceNote":"…",
            "asOf":"2026-10-01", "retrieved":"2026-10-02", "mock":false },
  "title":"Речник: бюджетът на разбираем език", "subtitle":"64 основни термина с обяснения и практически примери",
  "intro": { "lead":"За първи път срещаш тези понятия?", "text":"…",
             "disclaimer": { "bold":"Числата в примерите са условни.", "text":"…" } },       // disclaimer е ОБЕКТ, не низ
  "categories": [ { "id":"osnovi", "title":"Основи: как е устроен бюджетът", "short":"Основи", "from":1, "to":13 }, … ],   // 5
  "terms": [ { "n":4, "slug":"kfp", "title":"Консолидирана фискална програма - КФП", "name":"Консолидирана фискална програма",
               "abbr":"КФП", "cat":"osnovi", "def":"…", "example":"…", "aliases":["КФП"],
               "related":[ { "slug":"darzhaven-byudzhet", "note":"Различните обхвати не са взаимозаменяеми." } ],
               "see":[ { "label":"Виж в бюджета", "href":"#/izpalnenie/byudzheti" } ] }, … ],          // 64, n = 1..64
  "relationsTitle":"Свързани понятия",
  "relations": [ { "text":"Дефицит → Салдо, дълг, ново заемане", "from":"Дефицит", "to":["Салдо","дълг","ново заемане"],
                   "note":"Дефицитът е за период; дългът е към дата.",
                   "terms":["byudzheten-defitsit","byudzhetno-saldo","darzhaven-dalg","nov-dalg-novo-zaemane"] }, … ],   // 7
  "sourcesTitle":"Източници и поддръжка", "sourcesIntro":"…",
  "sources": [ { "name":"Министерство на финансите: Консолидирана фискална програма", "url":"https://www.minfin.bg/bg/383" }, … ] }   // 7, всички https
```
* `categories` са непрекъснати диапазони върху `n`, а `term.cat` е `id` на категорията: osnovi 1–13 (13 термина),
  danatsi-i-prihodi 14–29 (16), razhodi-i-merki 30–42 (13), defitsit-i-dalg 43–52 (10), kak-da-chetem-chislata 53–64 (12).
  Списъкът е в ред по `n`; групирай го по `cat` за заглавията на категориите.
* `slug` е уникален, с малки ASCII букви и тирета: стабилният ключ за изскачащо, дълбока връзка и всяко `related[].slug` /
  `relations[].terms[]`. `title` е заглавието; `name` е простото име без съкращението (равно на `title` при 61
  от 64; трите термина с `abbr` — `kfp`, `dds`, `bvp` — имат `title` = „name - abbr“). Търси се в `title`, `name`,
  `abbr` и `aliases` (13 термина имат синоними: други думи, които читателят въвежда; празен списък, когато няма). `def` и `example` са
  обикновен текст (без разметка); `example` ползва условни числа.
* `related` (24 термина) носи едноизречна бележка `note`; `see` (43 термина, останалите 21 имат `[]`) е връзката „Виж в бюджета“,
  чийто `href` е маршрут, който съществува в `routes.js` и води до **екрана**, който държи блока — старите котви на подблокове от
  едностраничния сайт вече не съществуват. 18 различни цели: `#/`, `#/prihodi`, `#/prihodi/{nedanachni, pomoshti, dds,
  akcizi, ddfl, korporativen, osiguritelni}`, `#/razhodi`, `#/merki`, `#/vedomstva`, `#/izpalnenie`,
  `#/izpalnenie/byudzheti`, `#/dalg`, `#/danaci`, `#/obshtini`, `#/prognoza`.
* `relations[].from` и `.to` са етикети за показване (низове, не slug-ове); `.terms` са slug-овете за свързване; `.text` е готовият
  ред „A → B, C“. `sources` са външни публични страници.

```jsonc
// guide.json — 8 стъпки, 5 проверки
{ "meta": { "id":"D23", "title":"Пътеводител: разбери бюджета стъпка по стъпка", "status":"real", "source":["wg"], "sourceNote":"…",
            "asOf":"2026-10-01", "retrieved":"2026-10-02", "mock":false },
  "title":"Разбери бюджета стъпка по стъпка.", "lead":"…",
  "steps": [ { "n":1, "title":"Започни с „Какъв е бюджетът?“", "verb":"Започни с",
               "screen": { "id":"S01", "label":"Какъв е бюджетът?", "href":"#/" },
               "intro":"…", "blocks":[ { "type":"p", "role":"note", "text":"…" } ],
               "next": { "n":2, "title":"Отвори „Откъде идват парите?“", "href":"#/prihodi", "text":"Следва: разбери откъде идват средствата." } }, … ],   // 8
  "checks": { "title":"Петте проверки", "heading":"Преди да използваш или споделиш число", "lead":"Провери пет неща:",
              "items":[ { "n":1, "short":"Период", "text":"за кой период е" }, … ],                  // Период, Обхват, Единица, Статус, Източник
              "end":"Използвай „Покажи източниците“ или раздела „Откъде са данните?“ за подробности.",
              "text":"…целият раздел като едно изречение…" },
  "credit":"Работна група „Бюджет на светло“" }
```
* Стъпките водят до S01 `#/`, S06 `#/prihodi`, S07 `#/razhodi`, S12 `#/merki`, S10 `#/vedomstva`, S15 `#/izpalnenie`, S17 `#/dalg`,
  S18 `#/danaci`; `screen.href` и `next.href` се проверяват спрямо `routes.js`. **`next` ОТСЪСТВА (не е null) на стъпка 8**:
  пътеводителят завършва с петте проверки, затова проверявай `if (step.next)`. `title` = `verb` + етикетът на екрана в кавички.
* Всяка стъпка има точно един блок, `{type:"p", role:"note"}`, бележката „какво да провериш на този екран“. `docs/data-spec.md` §3.17
  допуска `p|ul|link`; днес се среща само `p`, а страницата трябва да рисува непознат `type` като обикновен абзац, вместо
  да пада. `next` носи `href` и `text` освен `{n, title}` от §3.17. `checks.items` се рисуват като номериран списък под `lead`, затворен от `end`;
  `checks.text` е същият раздел като едно изречение (обикновен текст, ARIA, печат).
* **Къде това се различава от `docs/data-spec.md` §3.16/§3.17 (по-точен е този файл).** §3.16 показва `title` като съкращението и
  `name` като пълното име; файлът запазва оригиналното заглавие като `title` („Консолидирана фискална програма - КФП“) и
  простото име в `name`, с `abbr` само на трите термина, които имат такова. §3.16 не изброява нито `subtitle`, `intro`,
  `relationsTitle`/`relations`, `sourcesTitle`/`sourcesIntro`, нито `categories[].short/from/to`; всички те присъстват. §3.17 има
  `next{n,title}`; файлът добавя `next.href` и `next.text` и пропуска `next` на последната стъпка; има още `lead`,
  `steps[].verb`, `steps[].screen`, `checks.items[].short` и `checks.heading/lead/end/text`.
